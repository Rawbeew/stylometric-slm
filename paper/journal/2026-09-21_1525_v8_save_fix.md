## v7 save bug
After training completed, the save call raised:
```
RuntimeError: Some tensors share memory, this will lead to duplicate memory on disk
and potential differences when loading them again:
[{'encoder.encoder.embed_tokens.weight', 'encoder.shared.weight'}]
```

Cause: my `Classifier(nn.Module)` doesn't have `save_pretrained`, so the code fell to `trainer.save_model(out_dir + "/final")` which calls `safetensors.save_file`. The safetensors writer refuses to save tensors that share memory addresses (a tied-weight sanity check). The `TiedWeight` mechanism in MT5EncoderModel keeps `shared` and `embed_tokens` aliased to save memory, even after I cloned both.

**Result**: training metrics valid, model artifact lost. The 91.2% number is correct as a measurement, but the model cannot be deployed.

## v8 fix (committed: `00f8abd`)
New save path:
```python
final_dir = Path(out_dir) / "final"
model.encoder.save_pretrained(str(final_dir), safe_serialization=False)  # pickle .bin
torch.save({
    "state_dict": model.state_dict(),
    "author2id": author2id,
    "id2author": id2author,
    "hidden_size": hidden_size,
    "n_classes": n_classes,
}, final_dir / "classifier_head.pt")  # full state_dict pickle
tokenizer.save_pretrained(str(final_dir))
```

`save_pretrained(safe_serialization=False)` writes pickle `.bin` (handles aliased tensors via separate storage references in the pickle). `torch.save(state_dict)` also uses pickle. Both bypass the safetensors memory-aliasing check.
