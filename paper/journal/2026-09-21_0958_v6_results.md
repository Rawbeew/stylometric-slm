## Diagnosis (2026-09-21 morning)
Loaded model from HF and tested with `model.generate()`:
```
Expected='dickens'    Pred='<extra_id_0> the'    Match=False
Expected='hugo'       Pred='<extra_id_0>'        Match=False
Expected='zola'       Pred='<extra_id_0> class'  Match=False
Expected='manzoni'    Pred='<extra_id_0>'        Match=False
Expected='woolf'      Pred='<extra_id_0>'        Match=False
Expected='dickens'    Pred='<extra_id_0>'        Match=False
Expected='twain'      Pred='<extra_id_0>'        Match=False
```

**Root cause**: mT5 is pretrained with **span corruption** (denoising objective). Its decoder is trained to predict **`<extra_id_0>` / `<extra_id_1>` sentinels** that bracket masked spans. When we fine-tune for sequence-to-sequence classification (`input text → output author name`), the decoder has a strong prior to start with `<extra_id_0>` because that's its pretraining target.

So the model:
1. ✅ Successfully learned the input embedding
2. ✅ Loss is decreasing (model is *trying*)
3. ❌ Never fully unlearned the pretrain objective
4. ❌ Outputs sentinel tokens at inference time, not author names

## Why didn't v4 catch this?
v4 had the **front-matter leakage bug** (eval_loss 27.8) which masked this. With clean data (v6, eval_loss 10.6), the issue is now visible but only because we manually loaded the model and generated samples. The HF `compute_metrics` would catch it but we don't have any compute_metrics configured — only loss.

## Why wasn't this caught earlier?
1. **Loss was decreasing** in v6 — model was technically learning *something*
2. **No per-author eval during training** — only at the end, where the eval also fails (0% accuracy, not even sanity)
3. **The eval was using `model.generate()` but checking `pred == author`** — a string match — which silently fails when pred is `"<extra_id_0>"` or empty

## What should be done differently
1. **Switch base model**: use `t5-base` or `google/mt5-small` with proper sequence-to-sequence training. Or use `xlm-roberta-base` as an encoder + classification head.
2. **Better fine-tuning**: longer training (10-20 epochs), lower LR (1e-5 instead of 3e-5), warmup, label smoothing
3. **Add `compute_metrics`** to trainer that actually decodes predictions and compares to gold
4. **Sanity-check predictions** at end of every epoch by sampling 5 generations
